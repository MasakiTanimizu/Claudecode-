# STEP5: 麻雀ルール設計 — SixKa6PeiSanmaルールセット

「6華6北5等三麻」の確定仕様。このアプリは複数のルールセットに対応する構成を前提としており（下記「ルールセット抽象化」参照）、これはその1つ目の実装。

## 使用牌構成（総116枚）

| 種別 | 内訳 | 枚数 | 備考 |
|---|---|---|---|
| 萬子 | 一萬・九萬のみ（各4枚） | 8 | 2〜8萬は不使用。順子は成立しない。ワイルド牌ではなく通常の老頭牌として扱う |
| 筒子 | 1〜9筒（各4枚） | 36 | 5筒はドラ設定プリセットに応じて赤/青に着色 |
| 索子 | 1〜9索（各4枚） | 36 | 5索も同様 |
| 風牌 | 東・南・西（各4枚） | 12 | 北は風牌として存在しない（下記「北」参照） |
| 三元牌 | 白・發・中（各4枚） | 12 | 白のうち1枚は「白ポッチ牌」 |
| 北（抜きドラ） | 北のみ | 6 | 標準三麻の4枚から6枚に増量 |
| 華牌（抜きドラ） | 春・夏・秋・冬・マイティ×2 | 6 | 各1枚のみ |

## 山と王牌 — 崖ルール

**「王牌（触れない14枚）」という固定区画は無い。** 山は配牌後から単一の列として扱い、通常のツモも槓・北抜き・華抜きの補充ツモも同じ列の先頭から順に消費する。

- 最初のドラ表示牌は、ツモが始まる位置の隣の牌。常時2面表示（開局時から2枚）
- 槓のたびに、通常通り1面ずつドラ表示が増える（2面ずつではない）
- 槓・北抜き・華抜きの補充ツモは、専用の嶺上牌スペースを使わず、**本来次のプレイヤーがツモるはずだった牌を先取りする**。その次のプレイヤーはさらにその次の牌をツモる（山が1枚ずつ前倒しで消費される）
- 流局は、ツモ可能な部分（末尾のドラ表示確保分を除く）が0枚になった時点
- 四槓散了は不採用。槓の回数に上限は設けず、山が尽きれば自然に流局になる

## 抜きドラ体系

### 北

- ツモった北は「抜く（即座に公開・補充）」か「手牌に残す」のいずれかを選択できる。**通常に打牌して捨てることはできない**
- 手牌に残した北は、和了形が**国士無双・字一色・四喜和**のいずれかに該当する場合にのみ有効牌。それ以外の和了形では和了できない
- 手牌に残すことを選んだ場合、以後その北を打牌で捨てることはできず、対局終了までその手に留まる
- 北は誰の手からも捨てられないため、ポンの対象にはならない。暗槓のみ理論上可能
- 「抜いた」北のみ北ドラ加算（設定「北ドラ有無」ON時、1枚につき+1翻）の対象。手牌に残した北は対象外
- 上記の変更により、**国士無双は標準形（老頭牌9種＋字牌4種＝計13種）**、**四喜和（小四喜・大四喜）も役満一覧に含める**

### 華牌（春夏秋冬・マイティ×2）

抜くことはできるが、**抜いたこと自体はドラとして加算されない**（+1翻のドラ効果は無し）。価値は下記の個別特殊効果のみに由来する。

| 牌 | 効果 |
|---|---|
| 春 | 抜いた本人が、その時点で自分がそれまでに抜いている華牌の総数（今回の1枚を含む）と同じ枚数の祝儀チップを獲得する |
| 夏 | 抜いた本人が和了した場合、点数ランクが1段階アップする: 1翻→2翻→3翻→満貫→跳満→倍満→三倍満→役満→**5倍満（上限）**。「立直のみ」（下記）が同時に成立していれば5倍満まで格上げされる |
| 秋 | 抜いた本人の赤5・青5（5筒・5索）は、通常のドラ（1翻）ではなく「ドラドラ」として2翻扱いになる |
| 冬 | 抜いた本人が和了した場合のみ、下記「アリス」が発動する（全員対象ではない） |
| マイティ×2 | 抜いた時点で、自分がまだ抜いていない季節を1つ選んで同じ効果を発動する。春夏秋冬を全て抜き終えている場合は自動的に「春」として扱う |

すべて「**抜いた本人が和了した場合のみ**」効果が発動する（春夏秋冬マイティで統一）。

### アリス（冬の効果）

1. 和了確定後、王牌の隣（ツモ山側）の牌の下段を1枚めくる
2. めくった牌が和了者の手牌・副露に何枚あるかを数え、その枚数分の祝儀チップを獲得して次の牌をめくる
3. 一致がゼロになった時点で終了。それまでに獲得した枚数の合計が祝儀チップ総数になる
4. めくった牌が華牌だった場合は和了者がその場でその華牌を「抜いた」ことにする（該当する季節効果があれば追加発動）。裏ドラ表示でも同様

### 白ポッチ

- 白4枚中1枚を特殊牌として管理。**面子完成のボーナスは無い**
- 通常時（面前立直中の自摸以外）はただの白（役牌としてポン・カンも通常通り可能）
- 面前立直中に**白ポッチ自体をツモった場合のみ**、その1枚を自分の待ち牌の好きな1つとして扱い和了できる（ワイルド）
- 立直後に他家が白ポッチを打牌した場合、白そのものが待ち牌の場合に限りロンできる（ワイルドにはならない）
- 白ポッチ自摸和了時: 一発なら「チューリップ」＋サイコロ1回分の祝儀、一発以外なら「チューリップ」のみ。**ロンではチューリップ・サイコロは一切発生しない**

### チューリップ（白ポッチの自摸ボーナス）

旧アプリ（`docs/legacy`）の`runTulipStreak`を移植。王牌の続きから牌を1枚めくり、その「隣接牌」が全プレイヤーの手牌・副露にそれぞれ何枚使われているかを数え、その合計枚数分の祝儀チップを獲得する。

隣接牌の定義（本ルールセット向けに調整）:
- 筒子・索子（1〜9）: 数字の前後1つ（循環）
- 萬子（一萬・九萬のみ）: 一萬↔九萬を互いの隣接牌とする
- 風牌（東・南・西）: 自分以外の残り2種
- 三元牌（白・發・中）: 白→發→中→白の循環
- 華牌・北が出た場合: 和了者がその場で抜いたことにして次をめくり直す

旧アプリにあった「7p/7s3枚以上使用で連続めくり」は、対応する牌が存在しないため移植しない。

### 赤ドラ・青ドラ

プリセットは以下の2種類のみ:

| プリセット | 内訳 |
|---|---|
| 赤各4（全赤） | 5筒・5索の4枚とも赤 |
| 赤各1＋青各1 | 赤1枚＋青1枚＋通常2枚（5筒・5索それぞれ） |

青は赤と同じ5筒・5索の中の別カラーの1枚（別の数字の牌ではない）。

**青ドラの効果**:
- 通常のドラ加算: 持っているだけで+1翻
- 追加効果（面前立直で和了した場合のみ）: 和了した手牌に含まれる青の枚数だけ、王牌の外側を追加でめくれる（青1枚なら1枚、青2枚なら2枚）。的中した場合、的中枚数分の翻をドラとして加算し、同じ枚数分の祝儀チップも獲得する

### 祝儀チップの支払い方の基本ルール

春・秋・アリス・チューリップ・青ドラなど、祝儀チップが発生する全ての効果に共通:

- **ロン和了**: 放銃者が全額を和了者に支払う
- **ツモ和了**: 和了者以外の2人が、それぞれ同じ枚数を和了者に支払う（**折半ではなく2人とも全額**）

## 採用役一覧

### 1翻
立直 / 一発（設定でON/OFF） / 門前清自摸和 / 平和 / 断幺九（食いタン設定で喰い可） / 役牌（自風・場風・白/發/中） / 嶺上開花 / 槍槓 / 海底摸月 / 河底撈魚

### 2翻
オープン立直（下記） / ダブル立直（設定でON/OFF） / 七対子 / 対々和・三暗刻・三槓子 / 混老頭・小三元 / 混全帯幺九（チャンタ） / 一気通貫（筒子・索子限定）

### 3〜6翻
純全帯幺九（3/喰い2） / 混一色（3/喰い2） / 清一色（6/喰い5） / 七対子4枚使い（4） / 七対子8枚使い（6）

### 役満
四暗刻 / 大三元 / 国士無双（標準13種） / 四喜和（小四喜・大四喜） / 字一色（北を含む場合は7種） / 清老頭 / 緑一色 / 四槓子 / 九蓮宝燈（筒子・索子限定） / 天和・地和・人和 / 流し役満 / **役満「立直のみ」**（下記）

**九種九牌は不採用**（配牌時の幺九牌枚数による途中流局は発生しない）。

### オープン立直（2翻）

- 門前時のみ。立直宣言と同時に手牌をすべて公開
- 通常立直の1翻ではなく2翻
- 他のプレイヤーは、オープン立直者の当たり牌（多面待ちの場合は全ての当たり牌）を打牌できない
- 例外: ポンをした結果、手元に当たり牌しか残っていない場合に限り、その牌を切ることができる

### 七対子の変則形

- 七対子4枚使い（4翻）: 7対子のうち1種類を暗槓せず4枚のまま保持する変則形。標準の七対子とは排他
- 七対子8枚使い（6翻）: 2種類をそれぞれ4枚ずつ保持する変則形。上記2つとは排他
- 対象を暗槓すると通常の面子構成に変わり、この役は失われる

### 役満「立直のみ」

- 立直を宣言して和了すること。かつ、北（抜き・手牌保持問わず）・華牌（抜き）・ドラを一切保有・使用していない状態
- **成立している役が「立直」ただ1つだけの場合に限る。** 一発・門前清自摸和・平和・断幺九・役牌など、他のどの役が1つでも同時に成立していれば通常の翻数・符計算に戻る
- 立直後にめくられる裏ドラ・カンドラは、成立判定にも点数にも一切影響しない
- 多面待ちの場合、§の「オープン立直」と同様、全ての当たり牌が打牌禁止対象になる（判定ロジックは共通化できる）
- 夏（上記）が同時に発動していれば、さらに5倍満まで格上げされる

## 点数計算

- **符・翻**: 4人麻雀と同一の符計算・翻数×符の点数テーブル（満貫/跳満/倍満/三倍満/役満）を流用
- **ツモ損**: なし
- **点数の丸め単位**: 全ての点数計算は100点単位ではなく**1000点単位で切り上げ**（固定点数表・符×翻計算・本場ボーナス・ウマ清算すべてに共通）
- **1〜3翻の固定点数表**（4翻以上は通常の符×翻計算）:

| 翻数 | 親/子 | ロン | ツモ内訳 |
|---|---|---|---|
| 1翻 | 親 | 2,000 | 1,000オール |
| 1翻 | 子 | 1,000 | 1,000（非親）／1,000（親） |
| 2翻 | 親 | 4,000 | 2,000オール |
| 2翻 | 子 | 2,000 | 1,000（非親）／1,000（親） |
| 3翻 | 親 | 6,000 | 3,000オール |
| 3翻 | 子 | 4,000 | 1,000（非親）／3,000（親） |

- **オカ**: 無し
- **トビ（飛び）**: 飛んだプレイヤーは祝儀チップを3枚失い、その3枚は飛ばしたプレイヤーに譲渡される
- **ドラ表示**: 常時2面表示（開局時から）。槓のたびに1面ずつ増加。南家がドラ表示牌をめくる担当

### ウマ（完全順位制）

| 条件 | 2位 | 3位 | 1位 |
|---|---|---|---|
| 2位の素点が40,000点超 | ±0 | -40枚 | +40枚 |
| 2位の素点が40,000点以下 | -15枚 | -25枚 | +40枚 |

2位が40,000点を超えていれば2位のウマを免除し、その分を3位が単独で負担する（15+25=40枚）。

### 素点ボーナス

1位の最終素点に応じて、**2位・3位それぞれが**（折半ではなく両方とも）以下の枚数を1位に譲渡する。最も高い閾値のみ適用（非累積）。

| 1位の最終素点 | 各プレイヤーからの譲渡 |
|---|---|
| 80,000点以上 | 3枚 |
| 90,000点以上 | 5枚 |
| 100,000点以上 | 8枚 |

### 本場ボーナス

1本場につき、ロン和了は放銃者から+2,000点、ツモ和了は他家2人それぞれから+1,000点（オール）。

## 鳴き・喰い替え・後付け

- **チー**: 上家からのみ可能。ポン・カン・ロンは誰からでも可能
- **喰い替え**: 現物喰い替え・スジ喰い替えともに禁止
- **後付け**: 設定でON/OFF（デフォルトON）
- **食いタン**: 設定でON/OFF（デフォルトON）

## 対局形式・持ち点・飛び終了・延長戦

- **対局形式**: 東風戦（東場のみ）と半荘戦（東場＋南場）を選択式にする。**デフォルトは東風戦**（`matches.game_type`、STEP3参照）
- 持ち点・返し点は設定で変更可能（設定画面の既存項目）
- 飛び終了・延長戦は設定でON/OFF

## ルールセット抽象化（複数ルールセット対応）

このルールは`packages/mahjong_engine`内の`RulesetDefinition`抽象インターフェースの1つの実装（`rulesetKey: "sanma.six_ka_six_pei"`）として実装する。

```
RulesetDefinition（抽象）
├── rulesetKey        一意なID
├── playerCount        3 または 4
├── tileSet             使用牌の種類・枚数・特殊牌の定義
├── yakuTable           採用役・翻数・喰い下がり・役満の一覧
├── scoringRules        符計算・支払い方式・ツモ損の有無
├── specialTileRules    抜きドラ・特殊牌の挙動
├── flowRules           配牌枚数・王牌（崖）構成・流局条件
└── toggleSchema        そのルールセット固有の設定項目一覧
```

`RulesetRegistry`が`ruleset_key`から実装を解決し、CPU思考・クライアントUI・サーバー権威判定はすべてこのレジストリ経由でルールを参照する。新しいルールセットは`rulesets/`配下にディレクトリを1つ追加して登録するだけで良い（既存の`six_ka_six_pei_sanma/`には手を入れない）。

DBスキーマ（STEP3）では`rule_settings.ruleset_key`と`matches.rule_config`内の`ruleset_key`でどの実装かを識別する。

## 完成後のルール変更について

`matches.rule_config`は対局開始時のスナップショットのため、ルールを後から変えても過去の対局記録・リプレイは変化しない。`RulesetDefinition`はプラグイン構造なので、ルールの追加・修正はアプリのアップデート作業として行える（設計のやり直しは不要）。オンライン対戦では、マッチング時にクライアントとサーバーのルールセットのバージョンを揃える仕組みが必要（STEP9で設計）。
