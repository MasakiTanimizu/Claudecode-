# STEP8: CPU思考アルゴリズム

深層学習・探索木は使わず、シャンテン数・受け入れ枚数・危険牌評価に基づくヒューリスティック方式。難易度（初級/中級/上級）は同じロジックのパラメータを差し替えるだけで表現し、STEP3の難易度=レート対応（簡単0.5/中100/難200）とそのまま接続する。

## アーキテクチャ方針

- **配置**: `packages/mahjong_engine/lib/src/ai/`。純Dart、Flutter/Serverpod非依存。オフライン練習では端末上で、オンライン対戦のCPUフォールバックではサーバー上で、全く同じコードが動く
- **ルールセット非依存の設計**: シャンテン計算・受け入れ枚数・危険牌評価はルールセットに依存しない共通ロジック。北・華・白ポッチ・オープン立直などSixKa6PeiSanma固有の判断は`rulesets/six_ka_six_pei_sanma/ai_hooks.dart`が供給する「AIフック」として実装し、AI本体はそれを問い合わせるだけにする（新ルールセット追加時もAI本体の改修は不要）
- **探索方式**: ミニマックス探索やニューラルネットは使わない（隠れ情報が多くモバイルで即応答が必要なため）。牌効率・危険度をスコアリングして最良の一手を選ぶヒューリスティック方式。難易度はスコアリングの重み・ノイズを変えることで表現する

## CPUの1手番の意思決定フロー

1. ツモ
2. 和了できる? → できれば基本的にそのまま和了する（見送りはしない）
3. 北・華牌を引いた場合、抜く/残すを判断（難易度依存）
4. 暗槓が可能なら実行するか判断
5. 門前で聴牌していればリーチ可能かを判定し、通常リーチ／オープン立直／ダマテンのいずれにするか判断（難易度依存）
6. 他家に危険な気配があるかを判定し、あれば安全牌（現物・スジ・壁）を優先、なければ牌効率（シャンテン数・受け入れ枚数）を優先して打牌を選ぶ

## 鳴き（ポン）の判断

- 鳴いた場合のシャンテン進行度、失う面前ボーナス（立直・門前清自摸和・白ポッチのワイルド和了資格）、鳴いた後に残る役の有無を比較してスコア化する
- 後付け設定がOFFの卓では、役が確定しない形の鳴きを候補から除外する（初級でもここは正しく判定する。ルール違反級のミスはさせない）

## 難易度別パラメータ

| 軸 | 初級 | 中級 | 上級 |
|---|---|---|---|
| 牌効率 | 簡易判定。時々非効率な打牌（意図的ノイズ） | シャンテン数＋受け入れ枚数を正しく計算 | 受け入れ枚数に加え2手先の変化まで考慮 |
| 防御 | ほぼ無し | 現物・スジなど基本的な安全牌読み | 現物・スジ・壁・河読みを組み合わせた押し引き |
| 速度 vs 打点 | 常に速度優先 | 中庸 | 局面（点差・残り局数・着順）に応じて使い分け |
| 北・華の抜き/保持 | 常に即座に抜く | 老頭牌・字牌に偏った配牌では保持を検討 | 国士無双・字一色・四喜和が現実的な時は積極的に保持 |
| マイティの季節選択 | 未取得からランダム | 未取得から簡易優先度 | 局面に応じて夏・秋を優先 |
| 白ポッチのワイルド選択 | ランダム | 最高打点の待ちを選択 | 期待値（打点×残り枚数）で最適選択 |
| オープン立直 | 使わない | 使わない | 手牌の完成度・打点・他家の状況次第で採用 |
| ミスの再現度 | 意図的に緩いミスを混ぜる | ほぼ堅実、稀にブレる | ほぼ最適、僅かなランダム性のみ |

難易度はSTEP3・STEP7の「対戦」レート（簡単0.5＝初級 / 中100＝中級 / 難200＝上級）とそのまま対応する。オフライン練習・友人戦でも同じ3段階を流用する。

## 特殊メカニクスの意思決定（AIフック）

```
rulesets/six_ka_six_pei_sanma/ai_hooks.dart
├── shouldKeepKitaInHand()       # 北を抜かず手牌に残すか
├── chooseMightySeason()          # マイティを抜いた時にどの季節として扱うか
├── chooseHakuPocchiWait()        # 白ポッチ自摸時、複数待ちからどれを選ぶか
├── shouldDeclareOpenRiichi()     # 通常リーチかオープン立直か
└── shouldPursueAnkanForYontsu()  # 七対子4/8枚使いを狙って暗槓を避けるか
```

新ルールセット追加時は、AI本体（シャンテン計算・危険牌評価）を変更せず、そのルールセット側で上記フックを実装するだけで済む。

## CPU代打ちでの利用

STEP4の「切断時の猶予期間中のCPU代打ち」も同じAIを使う。代打ちの強さは、その対局の難易度設定（`matches.difficulty`）をそのまま引き継ぐ。

## スコープ外（将来課題）

統計・機械学習ベースのAI（強化学習等、Suphx/NAGA相当）は開発コストが大きいためv1では扱わない。「上級よりさらに強いCPU」が必要になった場合の拡張ポイントとして`ai/`ディレクトリの差し替えを想定しておく。
